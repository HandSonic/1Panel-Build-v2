# 1Panel v2 社区版构建

从公开源码编译 Core、Agent 和前端，默认覆盖 amd64、arm64、armv7、ppc64le、
s390x、loong64、riscv64 七种架构。保留缺失 XPack 模块时的社区版兼容逻辑，不声明
企业版能力。

定时构建从官方发现最新稳定版，手动构建可选择 stable、beta、dev 或明确版本。
已有历史输入保留在 `config/sources.json`；兼容的新版本自动解析为每次构建的
`resolved-source.json` 工件，无需向仓库逐版本增加 JSON。它固定源码、安装器、
依赖、工具链、资源和配置哈希，并随七架构构建和发布校验传递。
安装器资源必须与对应官方包一致；除当前与已固定提交外，还在已解析分支提交的最多 300 条官方历史中匹配。
GeoIP 直接绑定对应版本官方包，校验完整压缩包和成员大小、哈希，避免独立下载地址更新影响旧版本。
工具链必须满足两个 Go 模块和全部 npm engine。
缺失且无匹配修复锁的依赖、未知布局或不兼容安装器会在发布前明确失败，不能带错发布。
社区版源码构建与企业版官方下载包保持独立，下游仍须完成实际安装验证。前端使用 npm ci；稳定版
内嵌配置使用 stable/info，企业版、演示等开关保持 false。安装包离线资源与应用的
is_offline 功能模式不同，该标志保持 false。

构建和验证命令见 [English README](README.md#build-and-verify)。必须使用干净且
已提交的代码，并传入真实 BUILD_REPOSITORY_COMMIT。下载文件先进入临时目录，
全部通过非空及 SHA256 检查后才应用；不能仅凭已有文件或目录判断成功。

每个架构压缩包保留标准目录结构，并增加 manifest.json，记录源提交、安装器提交、
构建仓库提交、工具链、社区版标记和每个文件的大小/哈希。旁置校验文件使用相对
文件名；checksums.txt 和 build-manifest.json 覆盖整个矩阵。验证包含必需文件、
ELF 架构、哈希、路径安全和重复成员，拒绝空文件、错误架构及陈旧额外产物。

GitHub 每天北京时间 16:00 检查官方最新稳定版。已有七架构压缩包及校验文件时直接
结束；缺哪个架构就补哪个，仅缺校验文件时使用 GitHub 摘要补齐，不重复下载旧包。
正常构建验证后自动发布，上传结果核对服务端摘要及大小。手动开启 publish_candidate
才创建独立草稿候选；同一产物重试时保留已有附件、只补缺失项。发布准备只验证本地
产物，发布任务开始时读取当前 Release 状态。部分上传失败后可用原验证产物继续，
既有附件必须匹配；也可通过 promote-existing 显式选择原产物恢复，不重新编译。
CNB 只在标签或手动触发时构建，使用实际推送标签、安装 Bash/Python，并执行同一
验证，当前仅保存流水线产物。旧的直接 GoReleaser 流程已禁用。

版本固定改善可重复性，但基础镜像、系统包仓库和压缩时间戳尚未完全固定，因此不
宣称二进制/压缩包逐字节可复现。模拟单测和 ELF 检查也不等于所有架构都完成了真实
编译或服务运行测试。
